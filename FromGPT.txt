我结合你现有的 **AlexNet-K8s 分布式推理集群** 和新增的 **鹏城医疗模型双塔分布式推理架构** 看了一下，当前架构其实已经具备很多基础能力（scheduler、Redis任务管理、Prometheus监控、part1/part2切分），但它现在是**单模型、同构节点、静态调度**。

你希望改造成：

* **node1、node2：医院边缘节点**

  * 发起任务
  * 执行 Worker（模型前端）
  * 保留患者原始数据
* **node3：云侧数据中心**

  * 执行 Server（模型后端）
  * 处理高计算量部分
* **控制平面：智能调度模块**

  * 同时调度 AlexNet 和鹏城医疗模型任务
  * 根据：

    * 任务优先级
    * 当前节点剩余资源
    * 模型推理阶段
    * 延迟预测
      进行动态调度
* **测试脚本**

  * HTTP POST模拟医院提交任务
  * HTTP GET查询结果

整体应该演化成下面这种架构。

```
priority_queue
```

例如：

```
医疗急诊:
priority=10

普通预测:
priority=5

AlexNet测试:
priority=1
```

使用：

Python:

```python
PriorityQueue()
```

---

## 第二层：资源感知

Scheduler实时获取：

Prometheus:

```
node_cpu_usage

node_memory_usage

node_gpu_usage
```

形成：

```python
node_score=
0.5*CPU空闲
+
0.3*GPU空闲
+
0.2*memory空闲
```

例如：

node1:

```
CPU free 30%
GPU free 20%

score=0.28
```

node3:

```
CPU free 80%
GPU free 90%

score=0.84
```

优先node3。
